# Установка и первый вход

## Сначала выберите среду

Требуются Python 3.9+ и зависимость из `requirements.txt`. Для Claude Code папка
скилла обычно `~/.claude/skills/telegram`, для Codex — `~/.codex/skills/telegram`.
Все команды ниже запускаются из этой папки. На Mac/Linux используйте `python3`,
на Windows — `py`; внутри активированного venv можно везде `python`.

Подробная установка — в [README](../README.md). Минимально:

```text
python -m pip install -r requirements.txt
python scripts/setup_telegram.py setup
```

Мастер запускает сам пользователь в своём терминале. Не собирайте секреты через чат
и не пересылайте пользователю команды с его секретами внутри аргументов.

## Если API-ключей нет

Это штатный первый запуск. Мастер покажет [инструкцию](api-keys.md), включая вариант
при ERROR отдельно для Windows и Mac, и дождётся локального ввода полученных ключей.
Ассистент может сначала объяснить шаги по одному, уточнив ОС. Отдельно открыть
инструкцию без подключения к аккаунту:

```text
python scripts/setup_telegram.py api-guide
```

Секреты мастер вводит скрыто. По явному согласию на локальное сохранение он записывает
api_id/api_hash в `~/.tg/config.json`, затем предлагает вход по телефону, коду и паролю
двухэтапной защиты. Новую сессию сохраняет в `~/.tg/tg_session.session`. Существующую
авторизацию переиспользует. Обычные read/send-команды не начинают интерактивный вход сами.

Мастер не редактирует hosts, не создаёт приложение на сайте за пользователя и
не отправляет сообщения в чаты. Для регистрации и входа он связывается с Telegram;
код может прийти в официальное приложение или другим способом, выбранным Telegram.

## Где лежат данные

| Данные | По умолчанию | Переопределение |
|---|---|---|
| Ключи | `~/.tg/config.json` | `TG_CONFIG` — другой файл; либо пара `TG_API_ID` / `TG_API_HASH` |
| Сессия | `~/.tg/tg_session.session` | `TG_SESSION` — путь существующей или новой сессии |
| Ключи в Keychain на Mac | services `tg-api-id` / `tg-api-hash`, текущий системный пользователь | используется как резервный источник |

Приоритет ключей: полная пара из окружения → пара из JSON → пара из macOS Keychain.
Частичные пары не смешиваются между источниками: настройте обе переменные вместе.
Путь с `~` раскрывается в домашнюю папку; расширение `.session` в `TG_SESSION` допустимо.

JSON и session-файл содержат секреты: это не шифрование. На macOS/Linux новые файлы
создаются с правами 0600, каталог — 0700. На Windows POSIX-права не заменяют ACL;
храните данные в личном профиле Windows, не в общей или синхронизируемой папке.
Не переносите session-файл в репозиторий и не показывайте его ассистенту.

## Проверка

```text
python scripts/setup_telegram.py check
```

Проверяет существующий вход и связь с Telegram, не отправляя сообщений.
`check --offline` только проверяет наличие ключей и файла сессии — это не доказательство
валидности входа и доступности сети. Значения ключей команды не печатают.

## Если настройка уже есть

Чтобы переиспользовать существующую сессию, задайте `TG_SESSION` локально перед
запуском. Не копируйте SQLite-файл и не запускайте несколько процессов с ним одновременно.
Используйте соответствующие этой настройке API-ключи.

Если появились «Нет ключей», «Нет сессии» или «Требуется повторный вход» — запустите
мастер. Если конфиг повреждён или переменные заданы частично, сначала исправьте именно
этот источник; мастер не перезаписывает его молча. При `database is locked` завершите
другой процесс с этим session-файлом и повторите. Отсутствие сети не лечится повторными
запросами кода. Если Telegram просит подождать, выдержите его срок.

Для удаления доступа завершите соответствующий сеанс в Telegram → Настройки →
Устройства, затем удалите локальную сессию и ненужные ключи. Удаление файла само по
себе не завершает уже скопированные сеансы.
