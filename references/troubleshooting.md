# Диагностика доступа к сайту

Эта проверка относится к my.telegram.org, а не к авторизации Telethon. На время
проверки оставьте VPN выключенным и не меняйте сеть. Ассистент объясняет команды
до запуска; приведённые ниже status и curl ничего не меняют и не требуют ключей.

## 1. Проверить фактическую запись

Из папки установленного скилла, обычный терминал:

```text
python scripts/hosts_telegram.py status
```

Адрес `192.168.0.1` в начале вывода nslookup обычно обозначает DNS-сервер роутера,
а не адрес Telegram. Не делайте вывод о подмене по этому числу без полного ответа.

## 2. Проверить известный IP независимо от hosts

Windows, обычный PowerShell:

```powershell
curl.exe --noproxy "*" --connect-timeout 5 --max-time 15 -I -L --resolve my.telegram.org:443:149.154.167.220 https://my.telegram.org/
```

Mac, Терминал — та же команда, но `curl` вместо `curl.exe`:

```bash
curl --noproxy "*" --connect-timeout 5 --max-time 15 -I -L --resolve my.telegram.org:443:149.154.167.220 https://my.telegram.org/
```

## 3. Проверить обычное обращение с текущим hosts

Windows:

```powershell
curl.exe --noproxy "*" --connect-timeout 5 --max-time 15 -I -L https://my.telegram.org/
```

Mac:

```bash
curl --noproxy "*" --connect-timeout 5 --max-time 15 -I -L https://my.telegram.org/
```

Ожидаем 302 с перенаправлением на `/auth`, затем 200. Успех означает доступность
страницы входа при этой проверке, а не успешное получение API-ключей. `--noproxy`
убирает явный прокси для запроса curl, но не выключает системный туннель за пользователя.

- Прямой IP отвечает, обычное обращение нет → проверить hosts и сохранённые адреса.
- Оба отвечают, браузер нет → полностью перезапустить браузер, попробовать другой
  с тем же подключением; возможны его кэш, прокси, расширения и другие настройки.
- Оба не отвечают → проверить сеть, ограничения доступа и актуальность адреса.
  Не отключать проверку HTTPS-сертификата и не ставить случайный IP.

Эти результаты не доказывают необходимость hosts или конкретную причину блокировки.
Для сравнения с отключённой записью требуется отдельное согласование изменения файла.

## Очистить DNS после ручной правки

Эти команды меняют только кэш, не запись hosts. Закройте браузер перед выполнением.

Windows: «Пуск» → PowerShell → правой кнопкой → «Запуск от имени администратора».
Вставьте и нажмите Enter:

```powershell
ipconfig /flushdns
```

Ожидается сообщение об успешной очистке. **После этого закройте администраторское
окно: мастер setup нужно запускать в обычном PowerShell.**

Mac: в Терминале выполните по очереди, Enter после каждой строки:

```bash
sudo dscacheutil -flushcache
sudo killall -HUP mDNSResponder
```

Пароль локального администратора не отображается при вводе. При успешном выполнении
сообщения может не быть. Затем полностью перезапустите браузер (на Mac Command+Q).
При сохранении проблемы попробуйте другой браузер или перезагрузите компьютер.
Очистка системного DNS не гарантирует очистку всех внутренних кэшей браузера.

[Microsoft: ipconfig /flushdns](https://learn.microsoft.com/en-us/windows-server/administration/windows-commands/ipconfig) ·
[Cloudflare: очистка DNS-кэша](https://developers.cloudflare.com/cloudflare-one/traffic-controls/dns-policies/test-dns-filtering/#clear-dns-cache)
